---- Stage 1 : Project Setup + Dataset Preparation ----

1. intialize uv package manager
    `uv init`
2. create project folders by running setup.py
    `uv run python setup.py`
3. Add basic packages
    `uv add datasets pandas tqdm`
    uv.lock file will be created
4. download 'ai4privacy' dataset
    `uv run python src/data/inspect_dataset.py`
    inspects the first example and prints column names to understand the schema

5. prepare the dataset splits
    `uv run python src/data/prepare_dataset.py`
    - pulls from ai4privacy/pii-masking-openpii-1m (HuggingFace)
    - filters English only, shuffled with seed=42
    - train/val come from official train split (no overlap), test from validation split
    - validates every span: text[start:end] must equal value, raises on mismatch
    - saves to data/processed/ as train.jsonl (25k), validation.jsonl (2k), test.jsonl (3k)
    - asserts no UID overlap across splits


---- Stage 2 : Baseline Qwen3-4B Evaluation ----

1. add Modal (gpu provider)
    `uv add modal`
    `uv run modal setup`  then authenticate in browser

2. write evaluation/baseline_modal.py
    - Modal app: privacyguard-baseline
    - image built from nvidia/cuda:12.9.0-devel-ubuntu22.04, installs vllm==0.21.0
    - model Qwen/Qwen3-4B pinned to revision 1cfa9a7, downloaded into image at build time
    - test.jsonl baked into the image so it travels with the container
    - runs on L4 GPU, bfloat16, max_model_len=4096, max_new_tokens=384
    - thinking disabled via chat_template_kwargs={"enable_thinking": False}
    - prefix caching enabled (all samples share the same system prompt)
    - response parsed with 3-tier fallback: strict JSON → markdown block → brace extraction
    - entities aligned back to source text to get start/end offsets
    - only accepts the 19 OpenPII label types, anything else is dropped

3. write evaluation/metrics.py
    - strict exact-span evaluation: (start, end, type) must all match
    - reports precision, recall, F1, F2 (β=2, recall-weighted), pii_leakage_rate, over_redaction_rate, json_validity

4. run baseline on full 3000 test samples
    `uv run modal run evaluation/baseline_modal.py --limit 3000`
    saves results/baseline_predictions.jsonl and results/baseline_metrics.json

    Results (Qwen3-4B zero-shot, no fine-tuning):
        precision        : 0.7207
        recall           : 0.6280
        f1               : 0.6712
        f2               : 0.6446
        pii_leakage_rate : 0.3720   ← 37% of real PII missed
        over_redaction   : 0.2793
        json_validity    : 0.8997
        TP / FP / FN     : 14955 / 5796 / 8859
        generation       : 286s @ 10.5 samples/s, 1118 tok/s


---- Stage 3 : QLoRA Fine-Tuning Qwen3-4B ----

1. create training script
    `training/train_modal.py`
    - use Qwen3-4B with 4-bit NF4 QLoRA
    - LoRA rank=16, alpha=32, dropout=0.05
    - use W&B for tracking and Modal L4 for training

2. prepare training setup
    - train on 25k samples, validate on 2k samples
    - max length=2048
    - learning rate=2e-4
    - micro batch=1, gradient accumulation=8
    - train for 1 epoch

3. test training setup
    `uv run modal run training/train_modal.py`
    - run small smoke tests
    - compare batch sizes and memory usage
    - keep micro batch=1 with gradient checkpointing disabled

4. run full fine-tuning
    `uv run modal run --detach training/train_modal.py --no-smoke-test --repo-id rohitkmr8527/privacyguard-qwen3-4b-qlora`
    - train for 3125 optimizer steps
    - complete training in around 4.5 hours
    - save checkpoints in persistent Modal Volume

5. save trained LoRA adapter
    `rohitkmr8527/privacyguard-qwen3-4b-qlora`
    - final adapter uploaded to HuggingFace


---- Stage 4 : Fine-Tuned Model Evaluation ----

1. create fine-tuned evaluation script
    `evaluation/finetuned_modal.py`
    - load Qwen3-4B with trained LoRA adapter
    - use the same prompt, test data and metrics as baseline
    - evaluate on the frozen 3000 test samples

2. run full fine-tuned evaluation
    `uv run modal run evaluation/finetuned_modal.py --limit 3000`

    Results:
        precision        : 0.9562
        recall           : 0.9508
        f1               : 0.9535
        f2               : 0.9519
        pii_leakage_rate : 0.0492
        over_redaction   : 0.0438
        json_validity    : 0.9983

3. compare baseline and fine-tuned model
    `uv run python evaluation/compare_results.py`
    - saves results/baseline_vs_finetuned.json

4. check train-test data leakage
    `uv run python evaluation/audit_leakage.py`
    - no UID or exact text overlap
    - only 0.10% template overlap
    - fine-tuned F1 on unseen templates remains 0.9535
    - saves results/leakage_audit.json

5. Stage 4 completed
    - fine-tuned model shows large improvement over base Qwen3-4B
    - no meaningful train-test leakage detected


---- Stage 5 : Generalization Evaluation + Error Analysis ----

1. analyze OpenPII prediction errors
    `uv run python evaluation/error_analysis.py`
    - calculate per-entity precision, recall and F1
    - inspect false positives, false negatives and label confusion
    - save results/entity_metrics.json
    - save results/error_analysis.json

2. prepare external benchmark datasets
    `uv run python evaluation/prepare_external_benchmarks.py`
    - use 1000 samples from Gretel official test split
    - use 1000 samples from Nemotron-PII official test split
    - map only compatible labels to PrivacyGuard taxonomy
    - keep unsupported labels as ignored entities
    - save reproducible dataset revisions and mapping manifest

3. evaluate base and fine-tuned model externally
    `uv run modal run evaluation/external_eval_modal.py`
    - evaluate both models on Gretel and Nemotron
    - use strict exact span + type metrics

4. analyze generalization
    `uv run python evaluation/analyze_external_results.py`
